`D:\VibeCoding\TV\03-源码例程\01-出厂程序下载` 里共有 5 个固件，其中：

| 固件 | 适用硬件 |

| `ESP32-S3N16R8-WIFI-XIAOZHI-1.54-V1.3.0.1.bin` | N16R8 WiFi 1.54 寸（纯小智，无机器人控制） |

| `lovetv-merged-hybrid-backup.bin` | 4,572,976 B | 旧版（LoveTV + 小智共存），仅留档，一般不用 |

SHA256 校验（烧录前可核对文件是否正确）：

```
lovetv-merged.bin   91E3ECEDA6D04FFB91238039B5D3DC82E1FC4631751664BABA97BB88CB17D29A
factory-merged.bin  1A359B930EF13B01F07537138FCF878936B932CFCA61D7173A18B49BF0323E77
```

> ⚠️ 文件名很像，**烧 LoveTV 必须选 `lovetv-merged.bin`**；`factory-merged.bin` 只在恢复出厂时用。之前卡在“正在同步时间”屏幕闪烁，就是因为烧成了出厂固件，且设备里没有 WiFi 配置。

### 合并固件会清空 WiFi 配置

合并固件是从 0x0 起的连续镜像，中间空隙由 0xFF 填充，其中 **0x9000–0xd000 的 NVS 区会被一并擦除**（已实测确认该区域为 0xFF）。因此：

- 烧 `lovetv-merged.bin` 或 `factory-merged.bin` 后，**WiFi 配置会丢失，必须重新配网**。
- 只想更新固件、保留配网数据时，用下面第四节的 `idf.py flash` 或“仅烧应用分区”，这两种方式都不碰 NVS。

## 二、找串口

用 USB 线连接开发板，打开设备管理器查看“端口 (COM 和 LPT)”，记下 ESP32-S3 对应的 COM 号。

这块星智板子走的是 **ESP32-S3 原生 USB 串口**（设备管理器里显示为“USB 串行设备”，VID `303A`），不是 CH340/CP210x 转换芯片。因此烧录工具必须选 **USB 模式**；如果误选 UART 模式，就会报 `2-sync fail / strapping pins` 错误。板子未连接时烧录会失败。

## 三、Flash Download Tool 图形界面烧录（推荐）

对应飞书教程《Flash工具/Web端烧录固件（无IDF开发环境）》的做法：把合并固件烧录到地址 `0x0`。**注意本机必须用 USB 模式，不能用 UART 模式**。

1. 双击运行 `C:\Users\StoneShaw\Desktop\flash_download_tool_3.9.2\flash_download_tool_3.9.2.exe`。
2. 芯片类型选 **ESP32-S3**，工作模式选 **Develop**，加载模式选 **USB**（不是 UART），点 OK。
3. 第一行点 `...` 选择合并固件，例如 `D:\VibeCoding\TV\lovetv-xiaozhi\flash\lovetv-merged.bin`，地址填 `0x0`，**并勾选该行前面的复选框**。
4. 选对 COM 端口（本机为 COM6，设备管理器里“USB 串行设备”那一项）；SPI SPEED 选 **80MHz**，SPI MODE 选 **DIO**，FLASH SIZE 选 **16MB**；USB 模式下 BAUD 不生效，可保持默认。
5. 点 **START**，等待进度条走完、状态显示 **FINISH**。
6. 烧录完成后点 **RST**（或给板子重新上电）重启。

> 如果之前用 UART 模式试过，先关闭烧录工具再重新打开，确保没有其他软件占用 COM6。

烧录新固件：选 `lovetv-merged.bin`。

恢复出厂固件：同一操作，把文件换成 `D:\VibeCoding\TV\lovetv-xiaozhi\flash\factory-merged.bin` 即可（里面已包含原 bootloader、分区表、OTA 数据、语音模型和 `XIAOZHI-ESP32-ROBOT.bin`）。

> 注意：工具和固件路径都不要放在中文目录下，否则可能加载失败；本说明里的 `flash` 目录是纯英文路径，符合要求。

**报错排查**

- `2-sync fail / strapping pins`：几乎都是选成了 UART 模式，改成 USB 模式即可（本机 COM6 是原生 USB 串口）。
- 如果 USB 模式仍报同步失败：按住板子上的 **BOOT** 键不松，点 **START**，看到开始握手后再松开 BOOT；或先拔掉 USB，按住 BOOT 插入 USB，再点 START。
- 检查设备管理器里是否同时出现两个 COM（蓝牙占用的 COM 不能选），只选 VID `303A` 的“USB 串行设备”。
- 换一根能传数据的 USB 线、换个电脑 USB 口再试；供电不足也会导致握手失败。

## 四、esptool 命令行方式（备选）

方法 A（推荐，自动烧录全部分区，**保留 WiFi 配置**）：

```powershell
$env:MSYSTEM = $null
$env:IDF_PYTHON_ENV_PATH = "D:\Espressif\python_env\idf5.3_py3.11_env"
. "D:\Espressif\frameworks\esp-idf-v5.3.2\export.ps1"
cd D:\VibeCoding\TV\lovetv-xiaozhi
idf.py -p COM6 flash
```

本机串口为 **COM6**（设备管理器里 VID `303A` 的“USB 串行设备”）。

> `$env:MSYSTEM = $null` 是必需的：若当前 PowerShell 从 Git Bash 继承了 `MSYSTEM` 变量，`export.ps1` 会报
> `ERROR: MSys/Mingw is not supported` 并拒绝初始化。

方法 A2（最快，**仅烧应用分区**，适合改代码后反复验证）：

```powershell
D:\Espressif\python_env\idf5.3_py3.11_env\Scripts\python.exe -m esptool `
  --chip esp32s3 -p COM6 --before default_reset --after hard_reset `
  write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB `
  0x100000 "D:\VibeCoding\TV\lovetv-xiaozhi\build\xiaozhi.bin"
```

只写 3 MB 的 app，不动 bootloader / 分区表 / NVS，WiFi 配置保留。

方法 B（esptool 手动写入分段文件）：

```powershell
D:\Espressif\python_env\idf5.3_py3.11_env\Scripts\python.exe -m esptool `
  --chip esp32s3 -p COMx -b 921600 --before default_reset --after hard_reset `
  write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB `
  0x0 "D:\VibeCoding\TV\lovetv-xiaozhi\flash\lovetv-merged.bin"
```

写 `lovetv-merged.bin` 是刷 LoveTV；换 `factory-merged.bin` 即恢复出厂。

> 注意：LoveTV 固件关闭了唤醒词/AFE，因此它烧录的 `srmodels.bin` 是 4 字节空占位。恢复出厂固件时用合并固件即可，里面已包含原模型；若手动分段写，则必须同时恢复原模型文件（见下），否则小智的语音唤醒会失效。

恢复出厂固件（分段写入）：

```powershell
D:\Espressif\python_env\idf5.3_py3.11_env\Scripts\python.exe -m esptool `
  --chip esp32s3 -p COMx -b 460800 --before default_reset --after hard_reset `
  write_flash `
  0xd000     "D:\VibeCoding\TV\03-源码例程\02-出厂程序源码\XIAOZHI_ESP32S3_ROBOT\build\ota_data_initial.bin" `
  0x10000    "D:\VibeCoding\TV\03-源码例程\02-出厂程序源码\XIAOZHI_ESP32S3_ROBOT\build\srmodels\srmodels.bin" `
```

如果只想先恢复应用（不恢复模型，唤醒词会不可用），只写最后一行 `0x100000` 即可。

## 五、注意事项

- 烧录前建议先把当前固件备份一份：`python -m esptool --chip esp32s3 -p COMx read_flash 0 0x1000000 backup.bin`（16MB Flash 全量备份）。
- 烧录过程中不要拔线；失败重试时先按一下板子上的 BOOT 键再执行。
- 两块固件使用**同一份分区表**（LoveTV 未改动 `partitions.csv`），所以两者可以互相覆盖，不会出现分区错位。
- 配网数据（NVS）是否保留，取决于烧录方式：
  - 合并固件（0x0 整片烧）→ **NVS 被擦除**，需重新配网。
  - `idf.py flash` 或仅烧 app（0x100000）→ **NVS 保留**，WiFi 不用重配。
- **首次使用或未配过网时**，开机后设备会开一个无密码热点（`Xiaozhi-XXXX`），用手机连上后浏览器打开 `http://192.168.4.1`，按页面提示填入家里 WiFi 并保存；连上网后时间会自动同步，LoveTV 时钟页才会显示正常时间。

## 六、纯 LoveTV 固件的行为变化

从 hybrid 版（LoveTV + 小智共存）换到纯 LoveTV 后：

- **没有小智语音助手了**，长按不再切换到对话界面，也没有唤醒词。
- 按键映射：

- 界面：三页全部改成**粉底白字**，并去掉了所有 emoji（这是朋友间的通讯设备，不是情侣款）。
- 页面结构从「三页循环」改为「主界面 + 两个临时页」：

| 页面 | 何时出现 |
| --- | --- |
| 主界面（时钟） | 默认页，粉底白字，显示时间/天气/滚动信息 |
| 相识页 | BOOT 单击进入，再单击回主界面 |
| 消息页 | VOL+ 发送时、或收到对方消息时自动弹出 |

- 按键映射：

| 按键 | 动作 |
| --- | --- |
| BOOT 单击 | 主界面 ⇄ 相识页 来回切换（在消息页时回主界面） |
| BOOT 长按 | 背光亮度 60% → 100% → 30% 循环 |
| **音量 + 单击** | **发送“芜湖！”**；已在消息页时作为「收到/退出」确认 |
| 音量 − 单击 | 背光亮度循环（与 BOOT 长按等效，更好按） |
| 音量 +/− 长按 | 音量 ±20（纯 LoveTV 暂无声音，为 v2 语音留言保留） |

消息互动的完整流程（MQTT 模块接入后生效）：

1. 你按 **VOL+** → 本机显示「已发送：芜湖！」
2. 对方设备自动弹出消息页，显示「对方喊你：芜湖！」
3. 对方按 **VOL+** 确认 → 回一条 `check`
4. 你的设备显示「**起飞！**」

> 不再依赖双击手势。双击窗口原本是 50ms（小智 `Button` 封装写死的值），远短于人手双击的
> 150–300ms 间隔，导致双击永远被判成两次单击。虽然已改为 180ms，但主操作仍放在 VOL+ 单击上，
> 因为单击永远比双击可靠。

## 七、局域网配置页

设备联网后会在 **80 端口**起一个配置页，手机或电脑浏览器直接打开设备 IP 即可：

```
http://<设备IP>
```

设备 IP 有三个地方可以看到：

- 主界面底部的滚动信息里会轮播一条 `配置 http://192.168.x.x`
- 串口日志：`I (xxx) main: Config page: http://192.168.x.x`
- 路由器后台的客户端列表

页面上可以改：

| 分组 | 字段 |
| --- | --- |
| 天气 | 城市代码（页面内附常用城市对照表） |
| 相识页 | 年 / 月 / 日、底部文字、一句话 |
| 消息互通 | 本机 ID、对方 ID、MQTT 服务器、端口、用户名、密码 |

保存后**立即生效，不用重启**：城市改了会马上重新拉天气，相识日期和文字会即时刷新。密码只存在设备 NVS 里，页面不回显。

两台设备的 ID 要互为对方：一台填「本机 A / 对方 B」，另一台填「本机 B / 对方 A」。

> 底部文字用的是英文字体，建议只填英文和数字；中文会显示不出来。

## 八、烧录后如何确认正常

用 `idf.py -p COM6 monitor` 看串口日志，重点确认这几行：

```
I (xxx) LoveTv: Config: city=101010100 anniv=2019-09-01
I (xxx) LoveTv: SNTP synced: 2026-08-09 16:30:00                <- 授时成功
I (xxx) LoveTv: Weather task created, free internal heap=xxxxx   <- 天气任务起来了
I (xxx) LoveTv: Weather task running
I (xxx) LoveTv: Weather body 4833 bytes                          <- 天气接口通了
I (xxx) LoveTv: Weather: 晴 26℃ humidity 45% aqi 30              <- 解析成功
I (xxx) main: Config page: http://192.168.x.x                    <- 配置页地址
```

对应的异常信号：

| 日志 | 含义 | 处理 |
| --- | --- | --- |
| `Failed to create weather task!` | 内部 RAM 不足，任务没起来 | 贴日志给我，需要再压内存 |
| 没有 `Weather task running` | 任务创建了但没跑起来 | 贴完整日志 |
| `Weather request failed (city=...)` | HTTP 连不上 | 检查 DNS，或城市代码填错 |
| `Weather data not found in response` | 接口返回了但格式变了 | 日志里带前 80 字节，贴给我 |
| `SNTP not synced within 10s` | NTP 被路由器/运营商拦截 | 会自动回退 HTTP Date，看下一条 |
| `Time set from HTTP Date: ...` | 回退授时成功 | 正常，时钟能走 |
| 反复出现 `Starting LoveTV interface` | 设备在重启（多为栈溢出） | 贴完整日志，含 `Backtrace` |

- **配网期间屏幕显示的是状态栏提示**（热点名 + 网址），联网成功后 LoveTV 三页界面才接管屏幕。这是有意设计：hybrid 版会被 LoveTV 界面盖住配网提示，导致首次开机看不到热点名。
- 若开机后卡在配网热点、想强制重新配网：在 LoveTV 界面出现**之前**（即还没联网时）单击 BOOT 即可清除 WiFi 配置并重启。LoveTV 界面已经显示后，单击只会翻页，不会误清配网。
